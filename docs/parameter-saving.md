# 小车 Flash 参数保存

在「遥控」页打开「运动参数调节」，点击调参面板底部的「保存参数」，立即发送 **`save\n`**。
不会弹出保存面板、先查询 `params`、检查控制状态、停止本地遥控或批量发送参数。
使用已连接的 BLE 串口通道；SIM 和未连接时不发送。保存不以所选固件档案或通知订阅结果作为发送前置条件；没有收到回执时按超时处理。

## 操作流程

1. 可以直接保存小车当前参数，无需先发送全部参数，也无需在本次连接中发送过任何调参项。若只修改部分参数，发送对应项即可，其余沿用小车当前值。
2. 点击「保存参数」，小程序仅发送一条 `save\n`，随后在按钮下方显示等待及结果。保存过程中不改变本地控制开关或双杆目标。
3. 收到完整 `save:` 回执后显示相应结果。新版固件支持 `armed=true` / `enabled=true` 时直接保存，普通 `save` 不会因平衡控制已使能而被拒绝。保存期间双杆仍可操作，运动帧保持周期发送。

「参数状态」是独立入口，提供 `params\n` 查询及手动 `control off\n` / `control on\n`。
打开状态面板会查询状态，并按现有松杆规则清理当前双杆操作；该面板不属于保存路径。
手动关闭车端控制仍需要确认已扶稳车体；恢复控制后走固件正常稳定启动流程。

保存内容包括重心基准、姿态 / 速度 / 差速 / 腿部 PID 的 P/I/D，以及车端当前腿高和横滚目标。
小车固件将其写入 STM32 内部 Flash，断电后恢复。速度、转向和电机输出不保存。
现有松杆及停止运动会将横滚归零并保持腿高；保存按钮本身不会发送姿态或 PID 参考值。

## 命令与回执

新增四条命令均为 ASCII，末尾一个 LF `0x0A`，**不加 `@`**：

| 用途                 | 实际发送        |
| -------------------- | --------------- |
| 查看参数和状态       | `params\n`      |
| 保存参数             | `save\n`        |
| 关闭轮子平衡控制     | `control off\n` |
| 恢复正常稳定启动流程 | `control on\n`  |

`save all\n` 与 `save\n` 等价，小程序统一发送后者。
这些短命令每条只占一次 BLE 写入，与原有运动/调参帧共用串行传输队列。
原有 SoftEngine 运动及调参命令仍使用 `@...\n`。

| 回执前缀            | 显示结果                                                                    |
| ------------------- | --------------------------------------------------------------------------- |
| `save: ok`          | 保存成功                                                                    |
| `save: unchanged`   | 参数未变化，已经保存；视为成功                                              |
| `save: busy`        | 小车暂时忙，请稍后重试保存；若说明为 `system is starting`，提示小车正在启动 |
| `save: full`        | 参数存储区已满，提示通过高级维护回收后重试                                  |
| `save: invalid`     | 参数无效                                                                    |
| `save: flash error` | 保存失败，当前 RAM 参数仍保留                                               |

按 LF 收齐一行再解析，兼容 CRLF、BLE 拆包、多行合包及前缀后的说明文字。
`params:` 状态识别 `armed / unsaved / enabled / flash_valid`，兼容 `true/false` 与 `1/0`。
`control: off requested; wait for params armed=false...` 是固件手动停机回执中保留的旧说明；小程序仅将其用于确认手动关闭请求，普通保存不依赖该回执或 `armed=false`。
完整参数明细及原始回包保留在现有收发日志中，不覆盖输入框草稿或冒充遥测。

每条命令等待回执最长 5 秒。保存回执超时显示「未收到保存结果」，不显示成功，也不自动重试。
等待期间禁止重复保存及交叉提交参数 / 控制命令；蓝牙写入成功、模块 `OK`、无线 ACK 均不能确认保存成功。
断连、切换固件 / 通道、退后台及停止操作会清理当前请求和半行缓存，旧回调不会更新新会话状态。
实际 BLE 写入开始前收到的文本不能确认该次请求；过长未换行输入整行丢弃。

普通保存不会发送 `control off`、`control on` 或 `save recycle`。
新版固件在处理保存命令时截取参数快照，普通保存不改变平衡解锁状态、运动目标或 PID 历史。启动中或已有保存操作可能返回 `busy`，客户端提示稍后重试，不建议关闭控制。
本次未添加高级回收按钮；存储区满时不会自动擦除。
只有维护操作 `save recycle\n` 要求停止控制且 PWM 为零；擦除期间断电可能丢失旧配置。
