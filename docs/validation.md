# 测试与联调

## 已完成

- 静态检查：Prettier 格式检查、严格 TypeScript 检查与本地微信 API 类型校验。
- 自动测试：70 项测试通过，覆盖协议编码和边界、控制器停止与命令合并、微信 BLE API mock、页面联动。完整测试列表由 `npm run check` 输出。
- 原生模板检查：微信开发者工具自带 `wcc` 编译 1 个 WXML、`wcsc` 编译 2 个 WXSS，通过且无警告；没有将此项视为真机视觉验收。
- 横屏布局：检查 WCC 编译的 WXML 布局快照，覆盖 844×390、667×375 和 667×320；方向标记、双杆与停止按钮无整页溢出。该快照不代替微信真机渲染与触感验收。
- 真实串口：COM3 上 JDY-31 的版本、名称和波特率查询；详见 [硬件记录](hardware-check.md)。没有改参数或让机器人运动。

## 尚需真实 BLE 模块与手机

当前 JDY-31 不提供本工程需要的 BLE GATT 通道，所以以下项目尚未验证，不能用自动化 mock 代替。

| 场景                   | 检查点                                                                                        |
| ---------------------- | --------------------------------------------------------------------------------------------- |
| iOS / Android 首次连接 | 系统蓝牙权限、微信蓝牙授权、15 秒搜索停止、设备去重                                           |
| 端点选择               | 对照模块手册选择 UART 服务/写特征；如果 Notify 失败，仍可发但提示无法读取回包                 |
| 透传验证               | 模块 UART 设 115200 8N1，先接 USB 串口接收端，确认每个 R 帧完整、顺序正确、不拼接、不补 CR/LF |
| 模拟隔离               | 模拟界面显示 SIM，UART 接收端没有任何遥控帧                                                   |
| 小车架空               | 先零目标，精细档轻推前后左右；正向速度在线上应为负数，对照实际轮向                            |
| 双杆 / 松手 / 触摸取消 | 两指同时操作；左杆松开仅速度和转向归零，右杆松开横滚归零且腿高保持，另一杆继续生效            |
| 长按                   | 两杆独立计时，5 秒后该杆归中，另一杆不受影响；不能保证手机冻结后的停止                        |
| 停止运动               | 发送零速度/转向/横滚并禁用本地控制；平衡控制仍运行                                            |
| 页面切换 / 后台 / 卸载 | 尝试零目标后停发/断开；前台或重连后不自动启用控制                                             |
| 写超时 / 蓝牙关闭      | 提示异常、停止调度、不重发旧会话目标                                                          |
| 物理失联               | 记录固件仍保留最后目标的现有行为；完成车端 watchdog 前不能视为可靠失联停车                    |
| 横屏 / 小屏幕          | 固定横屏，双杆和中央参数一屏可见；尺寸变化清理双杆并重新测量，安全区和胶囊不遮挡操作          |
| SoftEngine             | 尚未适配的配置不可启用控制                                                                    |

建议新增固件通信超时归零、来源仲裁及可区分的执行确认后，再完成地面长距离测试。这是当前固件的实际边界，项目没有擅自修改固件仓库。
