# SoftEngine 串口适配（2026-09-12）

适用固件：本次更新后的 `car_firmware` / `feature/SoftEngine` 工作区。
旧 main 继续使用 main 配置，其历史协议审计见 [firmware-protocol.md](firmware-protocol.md)。

| 配置         | main                 | 本次 SoftEngine                            |
| ------------ | -------------------- | ------------------------------------------ |
| UART 默认    | 115200 8N1           | 115200 8N1，可用 CMake 修改                |
| 遥控文本     | `R ...`，不带换行    | `@R ...\n`，LF 结束                        |
| 最大遥控帧   | 20 字节              | 22 字节                                    |
| BLE 写入     | 一条命令完整写入一次 | 每片最多 20 字节，顺序发送，间隔 25 ms     |
| 接收边界     | UART 空闲事件        | `@` 开始、LF/CRLF 结束，300 ms 内收齐      |
| 固件运动超时 | 无                   | 500 ms，速度/转向/横滚归零，保持腿高与平衡 |
| nRF          | 旧配置               | 默认关闭，不参与控制启动门控               |

选择配置只改变发送协议，不会自动烧录或识别车上固件。切换前完成旧格式归零发送，
切换后需要再次启用控制。MCU 对速度/转向、横滚和腿高的限幅与本项目编码范围一致。

BLE 传输保持每次最多一条命令正在发送；一条分帧命令结束前，不会插入下一条命令。
发生断开、超时或分片积压时关闭会话，不补发旧尾包。固件遇到新 `@` 重新同步，
长帧、超时残帧、UART 接收错误后的残片不会被当作有效请求。

现有 JDY-31 为 Bluetooth 3.0 SPP；微信小程序的 BLE API 不能直接连接。
串口协议适配不改变模块蓝牙类型。仍需 BLE UART 模块，TX→PA10、RX→PA15，共地，
模块 UART 参数与实际固件一致。没有修改 JDY-31 的 AT 参数。

验证：严格 TypeScript、73 项 Node 测试通过，wcc/wcsc 编译通过。新增覆盖分帧顺序、
断开取消尾片、延迟尾片丢弃、配置切换和 main 格式兼容。
车端完成 C++ 回归及 ST-Link 板上注入验证；真实手机蓝牙收发与连接负载后的自平衡
尚未验证。原有 `TX` 仍只代表 GATT 写入回调成功，不表示车端执行 ACK。

在本机需要安装依赖时，推荐显式使用官方源，避免全局旧镜像源证书错误：

```sh
npm ci --ignore-scripts --registry=https://registry.npmjs.org
npm run check
```
