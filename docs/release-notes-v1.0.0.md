## 一句话说明

面向 WL1 轮腿机器人的原生微信小程序蓝牙遥控台：横屏手柄布局双摇杆实时控制，支持运行时参数调节与参数保存，无登录、无云端服务、无用户资料采集。

## 本次发布内容

### 连接与通讯

- 固定使用 `main` 通讯格式，页面无固件选择入口，降低误操作面。
- 自动搜索并连接 `D30SP_126BB2`，连接后自动选定 FFE0 服务的 FFE2 写入、订阅 FFE1 通知并提示「通讯已就绪」，无需手动选协议或通道。
- 支持短 UUID 与完整 UUID 等价比较；缺少可写 FFE2 时明确提示连接失败，不回退到 FFE1 写入。
- 未知模块保留通用服务发现流程，便于后续设备接入。
- 串行写入：同一时刻最多一条写入在途，命令间隔 ≥25 ms，控制周期 100 ms，不把一帧拆成多个 20 字节包。

### 遥控操作

- 固定横屏，左摇杆 / 中间参数屏 / 右摇杆的手柄布局。
- 左摇杆：上下控制前后速度，左右控制转向；12% 死区，标准 60 RPM、全量程 100 RPM、超级模式 150 RPM 三档，默认全量程。
- 右摇杆：上下调节腿高（44.5–78.5 mm，满行程 17 mm），左右控制横滚（−18–18°）；以本次触摸起点为基准，初次触摸中心不跳高度。
- 两杆互不打断：左杆松开仅归零速度与转向，右杆松开保持腿高并将横滚归零；持续按住不限时，保持目标并周期发送。
- 「停止运动」将速度、转向、横滚归零并禁用本地控制，平衡控制继续运行。
- `SIM` 模拟模式使用同一编码与调度流程但不调用蓝牙写入，可无硬件体验双摇杆。

### 运行时调参

- 中央面板顶部「运动参数调节」开关切换运行参数回显与调参界面，面板选择本地记忆。
- 五组参数：重心标定与电机输出死区、俯仰环、速度环、转向环、横滚环；每项同时提供滑块与数值输入框，双向同步，支持负数与 0.001 级小数精度。
- 编辑只改草稿，点击「发送」才下发，逐项发送，运行中也可调整；发送期间阻止重复提交但保持摇杆响应。
- 新增电机输出死区 `deadzone <0..1000>`，同时调整左右轮最小非零 PWM，`0` 为关闭补偿。
- 成功仅提示「已发送 · 未确认执行」，不把 GATT 写入成功当作 MCU 执行确认。

### 参数保存

- 面板底部「保存参数」直接发送 `save\n`，按完整 `save:` 回执显示结果，不弹窗、不预查询状态。
- 保存过程不归零运动目标、不关闭控制、不擦除回收；`save: busy` 提示暂忙稍后重试。
- 等待期间禁止重复操作，5 秒未收到回执提示「未收到保存结果」。

## 安全边界（务必阅读）

- 「启用控制」是小程序**本地开关**，不是固件解锁 / 上锁指令；每次连接和回到前台都不会自动恢复运动。
- 「停止运动」**不是断电急停**，机器人仍在运行平衡控制；首次验证请架空车轮并保留硬件断电手段。
- `main` **没有通信看门狗**，物理断连、手机挂起或断电可能使车端保持最后目标，客户端无法保证断线停车。
- 不要与 nRF 遥控器同时使用，它与 UART 之间没有控制源仲裁。
- 不展示虚构的车速、姿态、电量或执行状态；`TX` 仅代表蓝牙写入 API 成功，`RX` 是原始接收片段。

## 工程质量

- `npm run check` 全绿：Prettier 格式检查 + 严格 TypeScript 检查 + 128 项 Node 原生测试（0 失败）。
- 测试覆盖协议编码与边界、控制器停止与命令合并、调参范围与包长度、输入校验、BLE API mock、页面联动与生命周期。
- 微信开发者工具 `wcc` / `wcsc` 原生模板编译通过，无警告；横屏布局覆盖 844×390、667×375、667×320。
- 无运行时 npm 依赖，依赖锁定在 `package-lock.json`。

## 已知限制与未验证项

以下项**尚未通过手机微信真机验证**，请勿视为已验收：

- 手机微信端 BLE 链路（权限、搜索停止、分包透传、触屏遥控）——目前仅完成电脑 BLE 适配器实测。
- 运行中逐项修改参数的实际响应、原生输入键盘与多指摇杆的配合。
- 带负载的自平衡性能，以及地面长距离测试。

其他边界：

- 小程序端不能修改模块 UART 波特率，需在模块侧配置。
- 固件需支持运行时保存，否则重启后恢复上次保存值或编译默认值。
- 建议在固件补齐通信超时归零、控制源仲裁与可区分的执行确认后，再开展长距离测试。
