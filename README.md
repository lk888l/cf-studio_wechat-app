# CF Studio · 蓝牙遥控台

原生微信小程序 + 严格 TypeScript。首个设备为 WL1 轮腿机器人，当前页面统一使用 `main` 的 ASCII 协议，无固件选择入口；底层保留 `SoftEngine` 分帧编码。无需登录、云端服务或运行时 npm 依赖；没有用户资料采集。

## 运行时调参（2026-09-13）

左右摇杆中间的面板默认保留运行参数显示，顶部「运动参数调节」开关使用与「启用本地控制」相同的小框样式；打开后进入调参，关闭后回到运行参数回显。
提供重心标定与电机输出死区、俯仰环、速度环、转向环和横滚环五组；第一组可用 `deadzone <0..1000>` 同时调整左右轮最小非零 PWM（默认 0，即关闭补偿）。每项同时提供滑块和数值输入框，双向同步，调整后逐项发送，运行中也可调整。组内上下滚动查看更多参数。
记住面板选择，不自动保存或重发参数。初始值为固件参考值，发送状态不代表车端执行确认。
已分别核对 main 与本地 SoftEngine 的命令和能力差异，详见 [调参功能与参数表](docs/runtime-tuning.md)。

调参面板底部「保存参数」点击即发送 `save\n`，直接保存小车当前参数。无需先发送全部调参项，不弹窗、不查询状态、不检查本地或车端控制开关；只按完整 `save:` 回执显示结果。
已对齐支持运行时保存的新固件：平衡控制和摇杆周期发送持续运行，保存不会归零运动目标；`save: busy` 提示系统暂忙或启动中，稍后重试，不再要求关闭控制。
旁边的「参数状态」用于单独查询参数及手动关闭 / 恢复控制，不属于保存流程。
等待期间禁止重复操作，5 秒未收到保存回执提示「未收到保存结果」。保存命令为 `save\n`，不加 `@`，不自动关闭控制或擦除回收。
操作流程、回执含义与真机验证项目见 [参数保存说明](docs/parameter-saving.md)。

## 运行

1. 在微信开发者工具中导入本目录，使用已有 `project.config.json` 的 AppID；已启用 TypeScript 编译。
2. 遥控台固定横屏显示，采用左摇杆、中间参数屏、右摇杆的手柄布局。先打开顶部 `SIM`，启用本地控制后体验双摇杆；模拟模式不会调用 BLE 写入。
3. 用手机真机调试：进入连接页 → 对照右侧名称提示，搜索并连接 D30SP_126BB2 → 通讯自动就绪 → 启用控制。
4. 开发者工具模拟器不等价于手机蓝牙环境；已完成电脑 BLE 与小车实测，手机微信端仍需真机验证。

工程质量检查：

```sh
npm ci
npm run check
```

`check` 检查 Prettier 格式和 TypeScript，再编译隔离的 `.test-build`，执行 Node 原生测试。`npm run format` 可统一格式。测试覆盖编码边界、控制调度、触摸/生命周期及模拟微信蓝牙 API；没有把模拟测试标为硬件测试。依赖锁定在 `package-lock.json`，CI 使用同一命令。现有 2021 版微信声明文件启用 `skipLibCheck`，业务源码仍按严格模式检查；新 BLE 字段只做局部类型扩展。

安装微信开发者工具的机器还可运行原生模板编译检查：

```sh
npm run check:templates -- --devtools "你的微信开发者工具安装目录"
```

也可设置 `WECHAT_DEVTOOLS_HOME`。此检查只调用本地 `wcc` / `wcsc`，不上传代码或连接设备；本轮已经通过。CI 没有安装开发者工具，因此将该检查单独保留。

## 操作语义

- 启用控制是小程序本地开关，**不是固件解锁/上锁指令**。「参数状态」面板另设车端控制按钮；每次连接和回到前台均不会自动恢复运动。
- 左摇杆：上下控制前后速度，左右控制转向，使用 12% 死区和 标准 60 RPM、全量程 100 RPM、超级模式 150 RPM 三档，默认全量程；松开仅将速度、转向归零，不打断右手操作。
- 右摇杆：上下调节腿高，左右控制横滚。以本次触摸开始时的高度为基准，满行程升降 17 mm，两轴各有 12% 死区；初次触摸中心不会跳高度。松开保持最新腿高并将横滚归零，不影响左手速度和转向。
- 两杆握持不限时，持续按住时保持目标并周期发送；松手或触摸取消采用该杆松手逻辑。
- 腿高范围 44.5–78.5 mm，横滚 −18–18°。控制器默认最低腿高 44.5 mm，停止时保持当前高度。改变窗口尺寸、切换页面、退后台和停止操作会清理左右触摸，防止旧回调恢复操作。
- 中央参数屏默认显示实时**控制目标**（速度、转向、腿高、横滚），以及连接、发送数量和最近的原始 RX 片段及接收时间；可切换为分组调参。「参数状态」面板按需查询 `params` 的控制与保存状态，运动目标仍不代表真实车速/姿态；SIM 不伪造设备回传。
- “停止运动”将速度、转向、横滚设为零并禁用本地控制；机器人继续运行平衡控制，**不是断电急停**。
- `main` 没有通信看门狗，物理断连、手机挂起或断电可能使车端保持最后目标；客户端无法保证断线停车。车轮架空完成首次验证，并保留硬件断电手段。不要同时使用 nRF 遥控器，它与 UART 没有控制源仲裁。
- `TX` 表示蓝牙写入 API 成功回调，`RX` 是原始接收片段，`SIM` 是本地模拟；`R` 命令没有执行 ACK，不展示虚构的车速、姿态、电量或执行状态。

## 协议与分层

```text
pages/index             页面交互、生命周期、可见状态
control/controller      本地控制开关、最新目标合并、停止优先、周期发送
devices/profiles        设备能力、限幅、线协议编码、固件版本隔离
devices/tuning          调参分组、范围与精度、固件能力、调参命令编码
transport/ble           扫描、连接、服务/特征发现、串行写入、超时、会话隔离
services/lifecycle      App 后台事件转发
services/parameters     参数状态查询、车端控制命令、保存事务及完整文本回执
```

WL1 main 使用 `R <turn> <velocity> <roll> <height>`，前进速度在编码时取反。速度/转向/横滚使用整数，高度保留一位小数。最大帧 `R -150 -150 -18 78.5` 为 20 字节，不附加 CR/LF/补零。

主分支按 UART receive-to-idle 整块解析，不能跨包拼接，也不能拆解多条合并命令。每条命令只调用一次 BLE write，帧间至少留 25 ms，控制周期 100 ms；不把一帧切为多个 20 字节包。BLE 模块是否保持完整 UART 输出仍需示波器/串口抓取与小车实测。

控制器始终最多一条正在发送、一份可替换的最新目标及一条待发调参，停止覆盖待发运动并取消待发调参。写入超时后关闭会话，不重放积压指令。后台尝试归零后断开连接，无法保证系统暂停前回调一定完成。

页面控制器与调参面板固定使用 `wl1Main`，不提供固件档案切换。底层 `DeviceProfile` 和 SoftEngine 分帧编码仍保留，便于后续设备适配与协议测试。完整协议依据、提交 ID 和代码行号见 [固件协议审计](docs/firmware-protocol.md)。

## 真机验收

见 [测试与联调清单](docs/validation.md)。模块接线需 TX/RX 交叉、共地；车端 RX 为 PA10、TX 为 PA15。供电、电平按所选模块手册核对。UART 波特率在模块侧配置，手机 BLE 页面不能修改 UART 参数。

日志只在内存中保存最近 60 条，每条至多 256 字符；复制操作由用户触发。连接与日志页在横屏内独立滚动，主遥控台无需滚动。未保存设备 ID、控制开关或上一次运动目标，也未自动重连。FFE0 服务固定自动选择 FFE2 写入、FFE1 通知；缺少可写 FFE2 时提示连接失败，其他服务仍保留手动选择。
